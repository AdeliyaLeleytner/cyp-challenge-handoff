It calls the pinned official tutorial validator and adds the current Space's variance rule (the tutorial validator itself lacks that rule). It never adds noise or repairs a near-constant submission.

## Commands and receipt discipline

```sh
python3 -m night.submit_candidate --manifest PACKAGE/submission-manifest.json --ledger-dir CAMPAIGN/submission-ledger
```

This creates immutable `intents/<intent_hash>/` containing the intent, exact CSV, certificate and manifest. It imports no network client. The optional Gradio library is needed only for the root's later explicit `--send`; its installed version must exactly match the manifest. The adapter compares the live named API signature to the reviewed snapshot before uploading. Root may instead inject an official tool/client adapter exposing `api_info()` and `submit_once(arguments, file_path)`; the same checks and ledger still apply.

The send path makes exactly one dispatch. A durable exclusive attempt record is written before uploading. An accepted-pending reply, interrupted request, timeout or unknown reply is never automatically retried. Repeating any already-attempted CSV hash is blocked permanently by this runner. A distinct hash is also blocked during the12-hour local cooldown and while any prior accepted/unknown request remains unresolved. The guard is deliberately conservative for rejected attempts too. It cannot detect submissions made outside this ledger: root must refresh actual account/leaderboard status first, and the server independently enforces its cooldown.

Root can reconcile a prior accepted/unknown receipt by adding an immutable `attempts/<csv_sha>/reconciliation.json` with `csv_sha256`, `status` in `processed|rejected|not_received`, and a hashed `evidence` path record supporting the observed remote outcome. This does not lift duplicate-hash protection or the12-hour guard. No CLI bypass is provided. Pending acceptance is not a leaderboard result; verify the actual receipt, expected within2hours per current source, without duplicate submission.
