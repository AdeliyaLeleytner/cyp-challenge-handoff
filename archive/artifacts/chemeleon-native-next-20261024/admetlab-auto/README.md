# Автоматический сбор ADMETlab в Chrome

## Запуск на этом Mac

Вставьте в Terminal:

```bash
bash "/Users/adeliyaleleytner/Documents/ChatGPT/CYP Inhibition/artifacts/admetlab-auto/run.sh"
```

Больше вручную загружать пакеты не нужно. Скрипт:

1. Подготовит 65 текстовых пакетов для 32 421 уникальной молекулы, максимум 500 в пакете. Официальные train/test идут первыми.
2. Откроет отдельную вкладку в обычном Google Chrome, в рабочем окне ADMETlab.
3. Откроет вкладку «Enter a list of SMILES», вставит список по одной молекуле на строку, проверит его, нажмёт Submit и скачает CSV результата.
4. Проверит 120 ожидаемых показателей и каждую молекулу по raw_smiles. Порядок строк в ответе может меняться.
5. Перейдёт к следующему пакету, сохраняя результаты каждого шага.
6. Объединит результаты в одну таблицу.

Работает один браузер и один активный пакет. Это экономит память и не создаёт сотни одновременных расчётов на сервере. Между успешными пакетами — пауза 10 секунд. Предел 1000 указан на [официальной странице](https://admetlab3.scbdd.com/server/screening).

Нужны Python 3.10+ и установленный Google Chrome. На этом Mac они уже есть. При первом запуске автоматически создаётся локальная `.venv` и устанавливается Playwright 1.64.1. Отдельный Chrome или ChromeDriver не скачивается. Для режима обычного Chrome требуется включённая настройка «Вид → Разработчикам → Разрешить JavaScript из событий Apple». В твоём рабочем окне она доступна; скрипт проверен с этой сессией.

Перед запуском оставьте открытой вкладку ADMETlab, в которой ручной расчёт уже работает: скрипт выберет это окно. При первом запуске из Terminal macOS может попросить разрешить Terminal управлять Google Chrome.

Оставьте Terminal и рабочее окно Chrome открытыми. На Mac `caffeinate` удерживает компьютер от обычного простоя во время запуска; крышку ноутбука лучше не закрывать. Другие окна Chrome можно использовать как обычно. Скрипт использует текущее сетевое подключение компьютера и не меняет IP, прокси, user-agent или профили при ошибках сервиса.

По умолчанию используются текстовый ввод и пакеты по 500 молекул. Новая очередь находится в `~/Downloads/ADMETlab-results-500`; предыдущие CSV-запуски в `output` и `output-98` сохранены. На Mac по умолчанию используется обычная сессия Chrome (`--browser-mode current-chrome`). Альтернатива — отдельный профиль через `--browser-mode playwright`. Подготовка файлов сама по себе не отправляет запросы на сайт.

## Где результаты

В папке `~/Downloads/ADMETlab-results-500`:

- `results/admetlab_merged.csv` — объединённые исходные ответы ADMETlab с request_id и SMILES.
- `results/features.csv` — числовые признаки для нашего обучения; списки структурных предупреждений представлены числом совпадений, исходные списки остаются в merged CSV.
- `results/missing-or-pending.csv` — ещё не полученные молекулы.
- `results/status.json` — число готовых строк и статус complete/partial.
- `batches/001/`, `002/`, … — исходные списки smiles.txt, проверки текста и запроса, скачанные CSV, состояния, снимки и проверки соответствия.
- `events.jsonl` — журнал прогресса.

До полного завершения таблица может быть частичной. `complete.json` создаётся только при наличии всех молекул. Результаты только веб-режима; API feature=true сюда не подмешивается.

Для другой папки укажи `--output`, например `bash run.sh --output "$HOME/Desktop/ADMETlab-results"`.

## Продолжение и контроль

После Ctrl+C или перезапуска компьютера выполните **ту же команду**. Готовые пакеты пропускаются, скачивание с сохранённого URL результата продолжается без нового расчёта.

Посмотреть прогресс, в том числе во время работающего сбора:

```bash
bash "/Users/adeliyaleleytner/Documents/ChatGPT/CYP Inhibition/artifacts/admetlab-auto/run.sh" --status
```

Если отправка оборвалась и неизвестно, принял ли её сервер, скрипт не создаёт дубликат. Когда URL уже рассчитанного результата известен, его можно подставить:

```bash
bash run.sh --result-url "7=https://admetlab3.scbdd.com/server/result/ВАШ_ID"
```

Короткие команды `bash run.sh …` выполняйте из папки скрипта.

## Если сайт отказывает

При HTTP 429 скрипт сохраняет прогресс и останавливает отправки. В режиме Playwright и при скачивании CSV сохраняется Retry-After, если он доступен. Обычная навигация Chrome не раскрывает этот заголовок скрипту; при429 отправки в любом случае останавливаются. После восстановления доступа можно разрешить одну новую попытку ранее отклонённого пакета:

```bash
bash run.sh --retry-rejected
```

До истечения Retry-After повтор не разрешается. Новая 429 снова остановит сбор; бесконечных повторов нет. При timeout после отправки сохраняется неопределённое состояние, без повторного POST. CAPTCHA или изменение формы также требуют проверки, скрипт не пытается их обходить. СменаIP не гарантирует устранения причины 429.

## Дополнительные параметры

```bash
bash run.sh --prepare-only                 # только подготовить текстовые списки, не открывать сайт
bash run.sh --merge-only                   # объединить уже готовые пакеты
bash run.sh --delay 20 --timeout 1800       # пауза 20 с, ждать каждый расчёт до 30 мин
bash run.sh --input molecules.csv --output another_run --batch-size 500
```

Свой CSV должен содержать столбец SMILES. Дубли удаляются по точной строке SMILES, без химической стандартизации. Для другого входного файла или размера пакета нужна другая папка `--output`, чтобы не смешать состояния разных запусков. В нашей очереди SMILES уже подготовлены заранее.

## Проверка целостности SMILES

- Строки SMILES не канонизируются, не экранируются вручную и не обрезаются. Неожиданные пробелы/переносы внутри строк вызывают ошибку вместо незаметного исправления.
- В `smiles.txt` молекулы разделены только LF; CSV-файл на сайт не загружается.
- В основном режиме скрипт считывает фактическое значение textarea в обычном Chrome и проверяет посимвольное совпадение, количество строк и их порядок.
- Перед Submit повторно проверяются строка и сериализация формы через FormData/URLSearchParams. В режиме Playwright дополнительно проверяется исходящий HTTP-запрос. Допускается только стандартная замена разделителей строк CRLF↔LF; символы внутри молекул должны совпадать точно.
- В каждом пакете сохраняется `textarea-integrity.json` с SHA256. Режим Playwright также сохраняет `request-integrity.json`.
- Скачанный raw_smiles должен точно совпасть с исходным SMILES. Отдельный столбец smiles может содержать стандартизованное сервисом представление; оба сохраняются, сопоставление не опирается на порядок строк.

Все 32 421 исходных SMILES прогнаны через настоящее поле Chrome и получение формы локальным HTTP-сервером: 65 пакетов, точное совпадение всех строк. Дополнительно проверены стереохимия, заряды, соль с точкой, обратные слеши и нумерация колец с %. См. `smiles-integrity-check.json` и `native-chrome-integrity-check.json`. Это проверка передачи данных, а не расчёт ADMETlab.

## Проверка

Полный цикл проверен установленным Chrome на локальном тестовом сайте: вставка в textarea, отправка URL-encoded формы, Submit, переход на результат, скачивание CSV, переставленные строки, объединение, продолжение без повторного POST, ошибка 429/Retry-After, восстановление по URL и отказ при повреждённом или неполном результате. Эти тесты не отправляют запросы в ADMETlab. Они проверяют работу программы, но не гарантируют доступность внешнего сервиса.

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Парсер основан на ранее проверенных реальных CSV ADMETlab3.0. Исторические модели/обучение ADMETlab неизвестны; полученные значения являются прогнозами, а не экспериментальными измерениями.

## Прямой доступ через Wi-Fi при включённом VPN (25 октября)

`run-direct.sh` отправляет ту же web-форму method=2 через системный curl,
с привязкой сокетов только к Wi-Fi `en0` (`--interface en0 --noproxy '*'`).
Глобальные маршруты, настройки Chrome и VPN не меняются. TLS проверяется.
Это отдельный транспорт без браузера; веб-набор эндпоинтов тот же.
Очередь: оставшиеся 5155 официальных молекул, 11 пакетов до 500.
Результаты и журнал: `~/Downloads/ADMETlab-direct-official-500`.

Проверка 25 октября: GET формы HTTP200, первый POST500 HTTP429 от nginx,
Retry-After отсутствует. Новых признаков не получено. Очередь остановлена;
повторный запуск не повторяет отклонённый POST. Требуется восстановление
доступа у сервиса и явное решение о повторе, а не автоматическая смена IP.
`--status` показывает сохранённое состояние без сетевых запросов.

Локальный тест прямого транспорта: отправка/CSV/merge, точное соответствие
SMILES, отсутствие повторной отправки, остановка на429 и чужом raw_smiles.

## Chrome с отдельным маршрутом ADMETlab

25 октября установлен macOS host route `121.40.210.46 → 192.168.0.1 → en0`.
Маршрут по умолчанию остаётся `utun5`. Соединения реального Google Chrome

Маршрут применяется ко всем приложениям, обращающимся к этому IP, а не
только к одному домену. После перезагрузки/переподключения сети его нужно
проверить; автозапуск системного демона не установлен.

Запуск существующего обычного Chrome (без установки зависимостей):

```bash

```

Это 11 пакетов до 500 из оставшихся 5155 официальных молекул.
Папка результатов: `~/Downloads/ADMETlab-Chrome-direct-500`.
Перед каждым пакетом проверяются DNS, маршрут ADMETlab через en0 и маршрут
по умолчанию через VPN. SMILES проверяются посимвольно после вставки и
перед Submit; скачанный CSV сверяется по raw_smiles, без опоры на порядок.
Готовые пакеты пропускаются, неопределённые отправки не повторяются.

запуск её автоматически не разблокирует. Причина отличия от успешной
ручной отправки пользователя не установлена. Это не доказательство
постоянной блокировки браузера или IP.

`bash admetlab-route.sh --status` — посмотреть маршрут;
`--enable` — добавить маршрут с текущим Wi-Fi шлюзом (sudo);
`--disable` — удалить только этот host route (sudo).
Если DNS ADMETlab изменится, Chrome-runner остановится до отправки.
