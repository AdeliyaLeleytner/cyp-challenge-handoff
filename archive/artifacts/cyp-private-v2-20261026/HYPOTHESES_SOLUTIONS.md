# Independent hypotheses from public solution code

Private preparation, 26 October 2026. No fits, spending, publication, notifications or leaderboard calls that submit predictions were performed. These are proposals, not reproduced improvements. Public authors' effect sizes below belong to their own populations, splits and often selected histories. They are not targets or significance thresholds for this campaign.

## OS-H1 — The interval loss × precision-weighting interaction is the intervention

**Sources.** Scigantic [`INTERVAL_2X2_RESULT.md`](https://github.com/Scigantic/open-admet-challenge-cyp/blob/e70a2920d611684c9aaff07400d951e2e79dd5f6/training/chemeleon_arms/INTERVAL_2X2_RESULT.md), [`sagemaker_runner.py`](https://github.com/Scigantic/open-admet-challenge-cyp/blob/e70a2920d611684c9aaff07400d951e2e79dd5f6/training/chemeleon_arms/sagemaker_runner.py), and [`train_interval.py`](https://github.com/Scigantic/open-admet-challenge-cyp/blob/e70a2920d611684c9aaff07400d951e2e79dd5f6/training/chemprop_22/train_interval.py). Revision `e70a2920d611684c9aaff07400d951e2e79dd5f6`. The author's 2048-wide experiment reports MAE/uniform 0.7170 versus interval/uniform 0.6895, but MAE/inverse-variance 0.7187 versus interval/inverse-variance 0.7422. This is a sign-changing interaction, not a universal endorsement of interval loss.

**Mechanism.** Interval distance already discounts errors inside uncertain credible bands. Inverse-variance row weighting may discount broad-band compounds a second time and push the model toward the selected, narrow-band active population. Uniform interval training could learn a more useful ranking/decision surface across potency regimes. Our old loss campaign changed auxiliary normalization, checkpoint selection and precision as well as the objective, so its negative result does not isolate this factorial question.

**Matched experiment.** One component and one fixed data/assay table, not another full-ensemble sweep: a 2×2 MAE versus exact **L1** interval distance, each with uniform versus the same documented inverse-variance weights. Hold encoder architecture, initialization, folds, target transforms, auxiliary-head weights, precision, optimizer, batches and checkpoint criterion fixed. Start from a capacity-matched scratch model; pretrained versus scratch is a later separate factor. Retain censored/bounded labels as bounds. Unit-check train/eval scaling, absent-bound masks and loss normalization before any expensive run. Feed every component through the same frozen-bank ensemble evaluation; do not refit the deployment incumbent between arms.

**Forecast, uncertain.** A zero-to-about-0.03 component macro ST-RAE gain under uniform weighting is plausible from the author's result; the sign can reverse, and marginal ensemble benefit may be much smaller. This is not a promised blind gain. Inspect all five metrics, activity strata, CI widths and error correlations.

**Falsifiers.** The interaction disappears under matched transforms/checkpoint selection; gains are only a global shift/spread removable by the common serving transform; or the nominal advantage relies on one fold/seed, a few malformed bounds, or a changed auxiliary population. An interval arm worsening rank or the hard/low-support strata should not be presented as a generally better potency model.

**Cost.** Four arms × five folds = 20 component jobs for a clean one-seed comparison. The source reports roughly 5–40 minutes/fold, implying about 1.7–13.3 GPU-hours before setup; our hardware may differ. First profile one bounded numerical smoke job, then root can size the full factorial using a fresh quote. A one-fold pilot is implementation evidence, not the scientific result. Further seeds are confirmation only if the pattern merits them.

## OS-H2 — Separate assay conditions before coupling their observation models

**Sources.** Doctawho42 [`src/trunk.py`](https://github.com/doctawho42/CYPChallenge/blob/bf018b8311c5e7804674384aa5cc16b6c93db94b/src/trunk.py), [`verify/g1_calib.py`](https://github.com/doctawho42/CYPChallenge/blob/bf018b8311c5e7804674384aa5cc16b6c93db94b/verify/g1_calib.py), and [`docs/method_report.md`](https://github.com/doctawho42/CYPChallenge/blob/bf018b8311c5e7804674384aa5cc16b6c93db94b/docs/method_report.md), revision `bf018b8311c5e7804674384aa5cc16b6c93db94b`. Their empirical calibration fits screen log2FC from direct pIC50 via `log2(1 − E/(1 + 10^(h*(pC0 − pIC50 − d))))`. The code reports ranking improvement but direct-scale damage in an early calibrated arm (ST 0.767→0.955). These are author reports, not our reproduction.

**Protocol constraint.** Root's independently checked protocol says primary screen is **+NADPH**, while the requested direct target is **−NADPH**, and released Emax is signed. The public model does not include an explicit condition-specific potency/TDI state in that link. Its `CAL_E` is a fitted effective suppression parameter, not the released Emax column; `g1_calib.py` fits E/H from all paired direct/screen cells and assumes 49.5049505 µM. Thus copying this equation is an empirical auxiliary comparator, not a faithful mechanistic likelihood. Fixed global E/H also need fold-local re-estimation to avoid nuisance fitting across validation labels. Check the concentration against the original protocol.

**Mechanism and competing arms.** Preserve one representation and architecture across: (A) direct target plus an unconstrained/free screen head; (B) the honest empirical same-potency calibration comparator, with its nuisance parameters fitted only inside training; (C) a condition-correct variant with separate direct and +NADPH/preincubation potency latents, connected using observed paired-condition measurements and a molecule-dependent shift. Route the +NADPH screen through its own condition. Keep signed Emax as an observed readout until the original normalization gives a defensible observation model; never substitute it directly for a 0–1 efficacy. All arms should carry the same available heads/parameters where practical, with loss terms/routing as the factor.

**Forecast, uncertain.** Potentially more than a feature-only tweak if condition mismatch is a major source of target distortion; an order of 0–0.03 rank or 0–0.05 ST-RAE movement is a planning range, not an evidence-derived prediction. Direct-scale bias should improve specifically in compounds/enzymes where condition shifts matter. There may be no gain over a free auxiliary head.

**Falsifiers.** A wrong-condition or wrong-isoform link performs equally well; nuisance parameters saturate at bounds; the supposed gain disappears with fold-local calibration; or the corrected model improves screen fit while worsening direct potency/rank. If the released measurements cannot identify the proposed relationship, retain a statistical multi-task comparator rather than claiming kinetic/mechanistic parameters. The screen adds target cells to already present compounds in the inspected trunk; do not invent an extra-molecule count.

**Cost.** Use the small descriptor/frozen-feature trunk first, not a new large GNN. The source describes about half an hour per complete arm on its setup: roughly 1–2 CPU-hours for a three-arm pilot, or a short profiled GPU allocation if justified. Actual cost follows measured runtime and root's cap. No newly generated biological labels or ADMET requests are needed.

## OS-H3 — Learn an incumbent-anchored ordering correction without changing its deployment ruler

**Sources.** Scigantic [`scripts/build_r25.py`](https://github.com/Scigantic/open-admet-challenge-cyp/blob/e70a2920d611684c9aaff07400d951e2e79dd5f6/scripts/build_r25.py) fits L2-regularized signed deltas from an incumbent, then restores that incumbent's mean/SD; R25 leaves three CYP columns byte-identical. JacksonBurns [`src/hinge_blend.py`](https://github.com/JacksonBurns/cyp-challenge/blob/9cfa8fb412bd05ede7fe3d2f59c86744d480ba2e/src/hinge_blend.py) and [`docs/REPRODUCTION.md`](https://github.com/JacksonBurns/cyp-challenge/blob/9cfa8fb412bd05ede7fe3d2f59c86744d480ba2e/docs/REPRODUCTION.md) likewise preserve incumbent columns/placement. In contrast, [stir_bar's write-up](https://github.com/lachrymator/openadmet-cyp-challenge-public/blob/6afb664e6fb22c516952e020273ba91442f426db/README.md) reports failure of large cancelling signed coefficients. This is a useful competing explanation, not a consensus.

**Mechanism.** New predictions may add local ordering information while a whole-base refit or new placement destroys the incumbent's useful deployment scale. Fit a small correction in prediction-difference space against a fixed baseline bank, with explicit regularization, and compare it with nonnegative/convex alternatives. Separately test affine mean/SD restoration versus an exact incumbent-quantile permutation control. The latter isolates ranking from the entire marginal prediction distribution, not just its first two moments.

**Matched control.** Freeze the actual incumbent CSV/checkpoints and baseline bank for all arms. Keep untouched CYP columns byte-identical. Generate any validation bank using only that panel's training labels; public cached OOF or checkpoints cannot be called a matched evaluation on our outer holdouts if those models trained on other rows in the holdout. Split model selection, correction fitting and evaluation. Do not use new leaderboard feedback or dispatch probes in this private campaign.

**Forecast, uncertain.** Meta-fitting is cheap; a material gain requires new conditional rank information. Zero gain is entirely plausible given residual correlations in the public reports. Full-test mean/SD preservation does not ensure preservation on the unknown scored half, which is split by chemical series.

**Falsifiers.** Raw gains vanish under moment/quantile controls; signed coefficients cancel unstably across panels; or gains concentrate in one previously tuned CYP and reverse on fresh matched panels. If signed corrections merely exploit calibration or duplicated training chemistry, prefer the simpler convex model and describe the result as calibration, not new molecular information.

**Cost.** Meta-stage usually seconds/minutes on CPU once a valid common OOF/query bank exists. Bank generation is a real prerequisite charged to the shared baseline/component budget, not “free.” Public Scigantic/Jackson caches are suitable for a reproduction/scope audit first; no optimizer was run in this census.

## Reading cautions that apply to all three

- Jackson's `IntervalHinge` implementation uses **squared** interval distance, despite comments equating it to the official soft-RAE. Its row-wide bound mask also deserves an affected-row audit before porting. Do not treat that as the exact L1 scorer.
- Scigantic's current `train_interval.py` calculates inverse-variance weights but then uses `ones_like(w)` after a protocol amendment; some headers/table descriptions still say inverse variance. Source/config beats prose.
- Reported effects and current leaderboard rows are not interchangeable. Scigantic's latest live0.4300 is not identified with the released R25 cache. Jackson's live report links revision86213… (cp17), while current HEAD9cfa… includes a later cp19 candidate described as unsubmitted.
