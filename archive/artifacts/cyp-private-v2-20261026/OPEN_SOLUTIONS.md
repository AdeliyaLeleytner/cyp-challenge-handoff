# Public Direct Inhibition solution census — private audit

Snapshot: **26 October 2026,08:44UTC**. Public read-only board refresh:261 entries,35 report URLs and18 “Open Code=Yes” flags. This census triaged all34 third-party report links, searched public GitHub repositories (36 keyword matches), and inspected implementation/configuration for the principal accessible recipes. No fits, model execution, spending, scholarly literature retrieval, public writes or leaderboard dispatch occurred. Our deleted report was not fetched or republished.

[Machine inventory](SOURCE_INVENTORY.json) records revisions, artifact/access classes, inspection depth and every report link; [source hashes](SOURCE_SHA256.json) cover private snapshots.43 saved leading-source files were checked against exact Git blob hashes. Some supplementary cards/reports were only triaged, and a dashboard hit the2MB read limit; this is a finite public-source census, not proof no undiscovered private/public method exists.

## What the earlier work covered — and missed

The previous campaign deeply implemented Jeremy-derived components and the historical briford four-member recipe. Its claim to the “strongest open reference” initially meant the subset declaring **Open Code=Yes**. The archived board already linked stir_bar's write-up; its omission is explicitly admitted in the prior `notes/lachrymator-omission-audit.md`. The later audit corrected that distinction but still stopped at an unreadable Scigantic website and described JacksonBurns mainly as a substantial repository. It did not establish an inclusive implementation census.

This matters concretely: **Scigantic's public repository contains training tables/scripts and frozen OOF/blind predictions**, and was available before the last campaign. Its availability is not captured by its current Open Code=No flag. The old negative ST-RAE-loss result is also not an isolated loss test: the private `cyp-chemeleon-native-20261024/RESULTS.md` records simultaneous changes to auxiliary normalization, checkpoint selection and precision. These are coverage/attribution gaps, not evidence that copying a newly found recipe would have prevented the worse submission.

### Scigantic: the most consequential missed implementation

The [released recipe](https://github.com/Scigantic/open-admet-challenge-cyp/blob/e70a2920d611684c9aaff07400d951e2e79dd5f6/README.md) reconstructs **R25**, not necessarily the latest live entry. [Training documentation](https://github.com/Scigantic/open-admet-challenge-cyp/blob/e70a2920d611684c9aaff07400d951e2e79dd5f6/training/README.md) describes31,669 compounds and22 targets: four organizer direct heads, four screen log2FC heads, five ChEMBL potency heads, five AID1851 maximum-response heads, and four qHTS AC50 heads. The26-head variant adds TDI-condition potency and TDI-only compounds. The inspected runner uses one scaffold fold for OOF, the next for early stopping, and the other three for training; blind predictions average fold models. Public tables retain a documented blind-structure/AID1851 auxiliary overlap for native-recipe parity. Do not label this a blanket overlap-free dataset.

The [2048-width factorial](https://github.com/Scigantic/open-admet-challenge-cyp/blob/e70a2920d611684c9aaff07400d951e2e79dd5f6/training/chemeleon_arms/INTERVAL_2X2_RESULT.md) reports **MAE/uniform0.7170 → interval/uniform0.6895**, while **MAE/inverse-variance0.7187 → interval/inverse-variance0.7422**. The interaction changes the sign. Those are author results, not our reproduction. [Actual runner](https://github.com/Scigantic/open-admet-challenge-cyp/blob/e70a2920d611684c9aaff07400d951e2e79dd5f6/training/chemeleon_arms/sagemaker_runner.py) and [the smaller interval member](https://github.com/Scigantic/open-admet-challenge-cyp/blob/e70a2920d611684c9aaff07400d951e2e79dd5f6/training/chemprop_22/train_interval.py) need careful train/eval-unit and mask checks: the latter computes inverse-variance weights but actually uses uniform weights after an amendment, despite stale prose saying otherwise.

The [R25 builder](https://github.com/Scigantic/open-admet-challenge-cyp/blob/e70a2920d611684c9aaff07400d951e2e79dd5f6/scripts/build_r25.py) fits signed, L2-penalized deltas from an incumbent with Powell optimization, then restores incumbent mean/SD. R25 changes only CYP1A2 from R24; the other three columns are asserted byte-identical. Its same-OOF fitted scores are explicitly optimistic. The release documents small platform-dependent rebuild drift; no rebuild was run here because that script fits meta-weights.

**Do not attach the wrong score to this release.** Current live Scigantic is0.4300; the released R25 narrative reports live0.4436 and predates that upload. Its README also calls0.4436 an interim score, whereas the [organizers' interim table](https://openadmet.ghost.io/halfway-through-the-openadmet-cyp-challenge/) lists Scigantic0.4382/rank11. This is a board/file attribution inconsistency to reconcile, not a license to call the released cache a reproduced0.4300 solution.

### JacksonBurns: useful deployment discipline, with implementation caveats

The board links the [86213 revision](https://github.com/JacksonBurns/cyp-challenge/tree/86213d34157eeeea7635b6943c3f8c3798548514), whose author describes cached cp17 reconstruction. Current [HEAD reproduction notes](https://github.com/JacksonBurns/cyp-challenge/blob/9cfa8fb412bd05ede7fe3d2f59c86744d480ba2e/docs/REPRODUCTION.md) additionally contain cp18/cp19 candidates described as unsubmitted. Therefore live0.5133 cannot be assigned to cp19.

[Final assembly](https://github.com/JacksonBurns/cyp-challenge/blob/9cfa8fb412bd05ede7fe3d2f59c86744d480ba2e/src/regression_final.py) combines standardized prediction families, then applies public blind moments, OOF-to-blind factors and extra `F_SPREAD` shrinkage. [The hinge update](https://github.com/JacksonBurns/cyp-challenge/blob/9cfa8fb412bd05ede7fe3d2f59c86744d480ba2e/src/hinge_blend.py) provides an incumbent-preserving comparison, not an invitation to retune the leaderboard. [Fold code](https://github.com/JacksonBurns/cyp-challenge/blob/9cfa8fb412bd05ede7fe3d2f59c86744d480ba2e/src/cypfolds.py) explicitly reports that NumPy tie-breaking changed fold agreement to21.7%; preserve actual fold IDs rather than seeds alone.

The [interval arm](https://github.com/JacksonBurns/cyp-challenge/blob/9cfa8fb412bd05ede7fe3d2f59c86744d480ba2e/src/interval_arm.py) uses **squared** interval distance, although its comments call it the metric. That is not exact L1 ST-RAE. Its row-wide `hb.any` bound switch warrants a targeted affected-row audit before porting. These are reasons to audit the implementation, not to dismiss its useful cached lineage.

### adlvdl: data-domain and deployment-variance controls

[Submission22 provenance](https://github.com/adlvdl/cyp_competition/blob/5ab3d7c9792e09da3fd10a18971a6696bdd62ecb/submissions/22_pooled_seed_ensemble/20261023/PROVENANCE.md) specifies PubChem-pretrained Chemprop, frozenMonroe/Atom-JEPA TabICL and pooled challenge/public-data Chemprop. CheMeleon-TabICL receives zero weight. Nested scaffold5×5 OOF selects Caruana weights, while [deployment](https://github.com/adlvdl/cyp_competition/blob/5ab3d7c9792e09da3fd10a18971a6696bdd62ecb/notebooks/build_pooled_seed_submission.py) uses seed-mean members and acknowledges their narrower spread relative to single-seed OOF. That mismatch is relevant to serving, not a free extra gain.

The [four-arm conformer study](https://github.com/adlvdl/cyp_competition/blob/5ab3d7c9792e09da3fd10a18971a6696bdd62ecb/notebooks/26_monroe_conformers.py) separates embedding input route, stereochemical enumeration and xTB/Boltzmann averaging. Its [summary](https://github.com/adlvdl/cyp_competition/blob/5ab3d7c9792e09da3fd10a18971a6696bdd62ecb/experiments/26_monroe_conformers/summary.csv) changes regression macro0.7020→0.6965 and does not improve TDI macro. This supports route/identity controls, not an assumption that expensive3D features give a large ensemble gain. Shorku's [public data/method repository](https://github.com/Shorku/OpenADMET_Blind_Challenge_Predicting_CYP_Inhibition/tree/539f80389eb459c595eb8daaf29d3317f674fa64) is a useful dataset lead; structure/conformer counts must not be counted as independent assay examples.

### Measurement-model and write-up sources

Doctawho42's [report](https://github.com/doctawho42/CYPChallenge/blob/bf018b8311c5e7804674384aa5cc16b6c93db94b/docs/method_report.md), [dead-zone refit](https://github.com/doctawho42/CYPChallenge/blob/bf018b8311c5e7804674384aa5cc16b6c93db94b/src/abldead.py) and extensive negative controls deserve focused reproduction. However, [the trunk](https://github.com/doctawho42/CYPChallenge/blob/bf018b8311c5e7804674384aa5cc16b6c93db94b/src/trunk.py) sends direct potency through a shared Hill-like screen link with no explicit NADPH-condition latent. [Its calibration](https://github.com/doctawho42/CYPChallenge/blob/bf018b8311c5e7804674384aa5cc16b6c93db94b/verify/g1_calib.py) fits effective E/H from all paired direct/screen cells and assumes49.5049505µM. It does **not** read signed released Emax as a fraction. Given root's verified +NADPH-screen/−NADPH-direct distinction, reproduce this only as an empirical comparator; a mechanistically faithful version needs separate condition handling and fold-local nuisance fitting. The code itself reports improved rank with damaged direct scale in an early arm.

[stir_bar](https://github.com/lachrymator/openadmet-cyp-challenge-public/blob/6afb664e6fb22c516952e020273ba91442f426db/README.md) gives actionable ideas but no exact executable recipe:4,999 property-only blind-neighbour compounds, task-weighted calculated properties, per-embedding PCA budgets, nonnegative stacking and Mitra. The quoted Mitra comparison uses a TabPFN-v2 AutoGluon family, not our pinned modern v3.5 result. Its warnings about negative cancelling coefficients conflict usefully with Scigantic's signed corrections; test the context rather than adopt either rule universally.

[KNIMEST](https://github.com/KNIMEST/openadmet-cyp-model-report/blob/a24334881c82c36f39541aa13483231be1efe8f2/MODEL_REPORT.md) reports an especially useful warning: locally preferred OOF-screen-feature model T scored0.8111 blind, while diagnostic in-sample A scored0.5977 and was chosen after seeing blind results. This is evidence of validation/deployment mismatch and selection history, not permission to leak assay labels.

## Reproduction priorities, with no automatic promotion

1. **Cached serving lineage:** inspect/rebuild SciganticR25 and Jacksoncp17/cp19 in a private tracked experiment, keeping their different release/board identities. These rebuilders can fit meta-weights, so they were not executed in this no-fit census.
2. **One clean component factor:** objective×weighting at matched capacity/init and fixed data/precision/selection, followed by contribution to a fixed incumbent bank—not a full replacement campaign.
3. **Condition-aware empirical measurement study:** free screen head versus the documented same-potency comparator versus a condition-correct formulation. Do not infer kinetics or use signed Emax as a fraction.
4. **Validation/operator fidelity:** freeze actual fold IDs and incumbent vectors, account for OOF versus full-refit/seed-mean predictions, and test both mean/SD and full-rank-distribution controls privately. Public OOF/checkpoints cannot honestly evaluate an outer holdout they partly trained on.

The independent proposals are in [HYPOTHESES_SOLUTIONS.md](HYPOTHESES_SOLUTIONS.md); the concrete first-wave critique is in [CROSS_REVIEW_SOLUTIONS.md](CROSS_REVIEW_SOLUTIONS.md). The latter supports immediate fixed replay, structural feasibility and a bounded assay-data pilot, while withholding expensive training until its actual controls exist. No public source's rank, prose or threshold becomes this campaign's success criterion automatically.
