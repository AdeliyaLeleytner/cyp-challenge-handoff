# Minimal final outcome-policy adaptation proposal

Proposal only. Keep the full wrapper final-only; do not run it until every one of the32,421 exact request IDs has a recorded terminal outcome. Never call32,421 “successful predictions” if any rejection exists.

1. **Preserve the current complete-coverage invariant.** Queue identity, no duplicates/extras, exact raw/feature order and stable file hashes still apply to all32,421 outcomes. Report `outcomes_complete`, `numeric_prediction_rows`, `service_rejected_rows`, `unresolved_service_structure_rows` and `feature_eligible_rows` separately. The current one-rejection snapshot implies fewer numeric predictions, not missing collection coverage for that request.
2. **Use the documented base endpoint schema.** Audit the120 mapped base values separately from appended `::category=` columns. Require64 documented probability checks on applicable numeric outputs. Sparse rejection indicators are evidence/status, not an additional120 ADMET endpoints or automatically approved model predictors.
3. **Accept only documented rejection patterns as terminal rejections.** For the currently observed whole-row case, require all120 raw values to equal `Invalid Molecule`, all120 base numeric values to be blank, and every corresponding category flag to equal1. Unknown strings, mixed partial status, absent flags or unexpected numeric values remain review failures. Produce a request-specific rejection manifest with source/raw hashes and official-membership flags. No synthetic values or generic coercion of errors to zeros. The parser should not attempt numeric MW on rejected rows.
4. **Keep numeric-model eligibility explicit.** Every non-rejected base feature must be finite; no imputation of rejection rows. Check service graph identity independently. A numeric row whose returned structure cannot sanitize or has unresolved graph/stereo change is preserved as numeric output but is not silently admitted to fitting. Bind the separate approved feature-exclusion manifest by hash. Do not recast this as a service rejection.
5. **Apply the relevant supervision policy after feature auditing.** Official-only inputs use official labels and their approved feature rows. Historical experts retain their disclosed legacy policy. Fresh full-pool matched control/candidate inputs use the approved source28 union any approved feature-identity exclusions identically. At this snapshot that union has29 unique requests. Collection and raw prediction files remain complete and unchanged.
6. **Keep exit/report semantics discriminating.** Incomplete outcome coverage is distinct from rejected molecules. A fully covered snapshot can have valid documented terminal rejections. Unhandled status, unexplained numeric missingness, conversion error or unresolved/unapproved graph exception blocks the feature-ready claim. “Mechanical audit passed with documented exceptions” must enumerate the exceptions and cannot assert biological prediction accuracy.

Implement these as a small status-aware layer around the existing strict raw/numeric, MW/fChar, alert-index, stereo and probability checks. Keep the fixed queue unchanged and do not weaken unrelated checks. Use the two frozen cases here as regression fixtures: Cl must be counted as rejected with no numeric eligibility; Sb must be counted as numeric-returned but excluded under its separate manifest. Recheck the final snapshot because further explicit service outcomes may appear. This proposal and the local intermediate adapter have not modified the final wrapper or collector.
